# Source separation pilot for the Robby audio/video lab

**GPU update (2026-10-30):** TUSS now runs on CUDA GPU 0 by default in the lab. The audio and video analyses finish first; the video worker is temporarily unloaded for TUSS and automatically restarted before the request finishes, to avoid GPU memory exhaustion. Bandit remains on CPU. A 3 s fixture with MOSS and video running concurrently took 893.6 ms to initialize the isolated worker model, 915.8 ms for the first TUSS separation and 120 ms for the second speech pass; total wall time was 8.2 s including the concurrent audio/video, captions and ASR. An isolated warm GPU test measured about 55 ms per 3.008 s TUSS window, versus 4.20 s on four CPU threads. Those warm timings exclude loading and competing work. GPU and CPU outputs had relative RMS difference 0.000062 on that sample. PyTorch reported a peak 321 MiB of tensor allocations, excluding CUDA context and other process allocations. GPU headroom is limited and concurrent inference can fail; a failure is reported rather than silently falling back. Set `ROBO_TUSS_DEVICE=cpu` only as an explicit operator override. The existing browser test checks that the TUSS result says `cuda:0`. Run `benchmark_tuss_gpu.py` with the TUSS source and dependency paths on PYTHONPATH to repeat the isolated CPU/GPU comparison; it uses the authored `.runtime/lfm3-tests/speech-music.wav` fixture.

The measurements below are historical CPU baseline measurements unless explicitly labelled GPU.

The optional branch is additive: MOSS 4B analyzes the original audio and LFM3-VL analyzes video while an isolated subprocess separates each window. TUSS Medium or Bandit v2 Multi can be selected; the latter was still running after more than 150 s for a 3 s clip on four CPU threads, so it is not the practical default. TUSS uses the original 48-kHz mono model and prompts speech, musicbg, sfxbg; the optional second pass requests speech, speech. It does not detect whether two speakers exist, perform diarization, match identities across windows, or return identity/timbre embeddings. Speaker tracks are unverified candidate estimates, not people.

Three category tracks and optional speaker tracks are returned as 16-kHz 64-kbit/s MP3 players. The existing local LAION sound-effect captioner processes nonquiet stems; captions are speculative and are not transcripts. Existing Humaneness Ears produces uncertain short-term emotion and vocal-trait impressions for speech-like stems, while the already-active Parakeet v3 transcribes them. These shared single-flight workers may be busy; errors and skipped stages are visible. No model is switched solely for the lab. The RMS skip threshold is 0.001, an energy heuristic, not reliable source-presence detection. The ASR path used here exposes no verified word timestamps. Media and separated WAVs exist only in a request-scoped temporary directory and are deleted on completion; the resulting playback bytes are returned to the requesting browser. CPU time and memory, and shared worker use, can affect Robby's live conversation.

`benchmark_stem_lab.py` generates a single synthetic, overlapping 3-second mixture from espeak-ng voices, authored music, and generated impulses. In one run TUSS took 4.03 s (RTF 1.34), and the optional second two-speech pass 2.65 s. A simple same-signal SDR comparison in dB, mixture to separated track, was speech 1.77 → 6.15, music -5.03 → 12.21, effects -7.15 → 24.63. These values are not a real-world benchmark, do not validate speaker identities or perceptual quality, and can be sensitive to alignment and level. With a 1-s stride, 4 s per 3-s window is about four seconds of separator work per second of new input before concurrency effects; this is not real time. Overlapping windows are independent, not seam-correct continuous streaming.

The HTTPS browser test `browser_stem_lab_check.py` uses synthetic camera and sound. In one 3-s two-speaker-option test total wall time was 11.2 s with the audio/video branches active, demonstrating functional playback and individual stage timings; the timing is not a robust performance distribution. The sound captioner can invent events in separation leakage; the TUSS two-speech pass produced a second low-energy track even for a single source. A model's description must not be interpreted as confirmed source presence.

FastDialogueSidon (official `higurashi-ai/FastDialogueSidon`, weights revision `daa52c2df05813cb7295cd77d85cd485b810fdc6`, Triton source `da37ddda3485a3c0704dc9333f891aca1ef0ba52`) was tested separately on GPU 0 after temporarily unloading only this lab's audio/video models. With torch 2.8 / CUDA 12.8, on a padded 4-second speech-plus-music synthetic clip, model load was 5.17 s, initial call with graph setup 1.66 s, and two warm synchronized calls 7.2 and 7.0 ms. These times exclude reading audio and model loading, and the test does not evaluate actual overlapping-speaker separation quality. The project documents CUDA graphs and an H100-oriented Triton backend. It is not currently selectable in the live lab because the two lab models leave less than 1 GiB free; running it concurrently would risk out-of-memory failures. Its output identity ordering and quality remain unvalidated.
