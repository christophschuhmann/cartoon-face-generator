What changed

  1. Moondream Parakeet Ultra runs on GPU 1 for final ASR and TTS boundary checks. Original v3 remains the boundary fallback.
  2. Final recognition reads the complete microphone buffer after the neural speech pause, without waiting for delayed preview features. Resumed speech still cancels an obsolete final result.
  3. The same FP32 ECAPA speaker model runs in a private GPU worker while ASR is working. It uses original microphone audio, with exact-waveform cache validation and CPU fallback.
  4. Long first audio buffers need only a 180-ms scheduling reserve; short buffers keep 300–350 ms. Old network gaps no longer impose a permanent 650-ms delay.
  5. Both normal TTS context sizes are warmed before readiness. A previously missing 1024-position bank caused a measured 71.75-second compilation stall.

Speaker checks and end-to-end limits

The GPU ECAPA vectors matched the CPU vectors at cosine 1.0 to displayed precision in four synthetic clips (maximum coordinate error below 1.1e-6). Warm CPU calls took 319–351 ms; GPU HTTP calls took 48–120 ms, including initial shape overhead. Overlap often reduces foreground speaker wait to 7–18 ms. The acceptance threshold was not relaxed.

Actual HTTPS browser runs use a real AudioWorklet with synthetic microphone fixtures and real ASR, isolation, API LLM and TTS. First verified TTS audio varies with the sentence; the external LLM also varied from 0.56 to 3.00 seconds before its first sentence. Playback lead was 195 ms for long first buffers or 315–365 ms for short ones. Stages overlap: do not add their timings.

No physical microphone, loudspeaker or DAC timing was measured. Camera cost, room echo and accents need separate real-user trials. Output verification may still reject generated speech and trigger retries. Unknown/background speaker filtering remains approximate.

Conversation regression checks

The full HTTPS VoxLock two-person test passed. The first Scicom run exposed a short TV continuation falsely matching a known voice and one TTS sentence failing verification. Both failures are retained in the report. Short non-wake continuations immediately after rejected speech now use up to four seconds of adjacent original voice context, without changing the transcript or threshold. After this repair, the full Scicom retest passed: both people registered, a known person returned, unknown TV was rejected, and no browser or speech error occurred. These synthetic tests do not prove perfect real-room performance.
