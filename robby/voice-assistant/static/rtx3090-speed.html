First PCM measures packet arrival, including any initial silence. The separate quality probes received their first nonquiet chunk after roughly 127–139 ms. The benchmark uses the same text, voice, temperature and guidance; the optimized sampler/precision can change sampled tokens and durations.

What changed

BF16 merged policy weights, content-hashed reference caching, early streaming release with a final cutoff, a 3→6→12→20-frame chunk ramp, semantic CUDA graphs with compiled decode, codec CUDA graphs and fused Triton kernels, and the Triton local codebook decoder. The torch.compile local sampler failed with the installed older PyTorch and is disabled; the published Triton path runs instead. Temperature zero has an explicit greedy fallback. Model warm-up is required after restart.

End to end

Real Chrome with a synthetic microphone, through the existing HTTPS demo. Timing runs from the final audible microphone block to scheduled browser output; excludes the physical device. No baseline whole-pipeline comparison was made in this session. The final microphone test uses the last audible block because the authored wake phrase can contain a long internal pause.

Quality and limits

Four authored German fixtures, including expressive prompts and temperature zero, produced finite audible PCM and zero Parakeet WER. Codec graphs reproduced bit-identical BF16 waveforms on three fixed seeds. This does not establish unchanged subjective naturalness or speaker similarity across arbitrary inputs. The browser start reserve stays around 300 ms for small first chunks; smaller reserves previously caused jitter. Background load and cloud LLM latency vary.

Reproduce

See RTX3090_OPTIMIZATIONS.md and the upstream INFERENCE_OPTIMIZATIONS.md. Use rtx3090-speed.env with the pinned upstream TTS runtime and the zero-temperature patch. Run live_latency_benchmark.py serially, then rtx3090_quality_check.py and browser_mouth_to_ear.py. Never run the separate engine benchmark concurrently with a latency measurement.
