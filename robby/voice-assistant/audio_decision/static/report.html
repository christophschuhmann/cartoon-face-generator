The useful conclusion

9 November update: New experiment: batch unchanged 64-class groups together. It measures additional speedups in an isolated prototype. The original deployed-path and live measurements remain below.

All 527 classes take about 2.3–2.5 seconds per window in the original deployed fast configuration: BF16, multi-label choice, 64 classes per group, with shared audio features. Binary groups of 16 take about 7.3 seconds for a ten-second history. Neither sustains all classes every 100–300 ms. A selected 16-class live view is much more responsive.

Temporal focus is not reliable enough to call this a validated SED system. An early beep was still reported in the final, silent interval. Repeating the target audio did not solve this. The page exposes the failure rather than replacing the model with fake probabilities or a different classifier.

Optimization, startup and memory

  • Model load: 17.579 s. First inference / kernel warm-up: 11.127 s, shown separately from warm times.
  • Reusing audio preprocessing and projected features reduced the 100-class binary comparison from 2.341 s to 1.645 s. Maximum absolute score difference: 0.0.
  • About 4157 MiB PyTorch allocation and 5922 MiB reserved in these tests; CUDA context overhead is additional. Loading requires at least 6 GiB free. The model remains loaded until the optional AV lab needs its slot.
  • Official model.compile() was tested and failed with InternalTorchDynamoError on this Torch 2.6 installation. It is not enabled. No shared CUDA or Torch upgrade was performed.
  • Language-model KV reuse across question groups is not assumed safe: the official decision-set forward uses joint bidirectional processing. Audio features alone are cached within a window.

Existing MOSS Audio + LFM3-VL lab returned HTTP 200 after idle d1 unloading; cold load and a three-second fixture analysis took 170.7 s. Robby ready afterwards: True.

Temporal-focus counterexample

Authored two-second recording, 880 Hz beep at amplitude 0.2 for 200 ms, either at the start or end, or no beep. Target: final 200 ms. Binary questions, fixed misleading swimming-pool scene context, five classes. This is a small diagnostic, not an AudioSet accuracy estimate.

“Early” means the target is silent. A higher beep score there than for “late” is a failure of time localization. Silence also receives nonzero sound scores. Raw exports preserve this evidence. A realistic next evaluation would use labeled onset/offset recordings, counterfactual contexts, multiple durations and per-class calibration, rather than treating the grid resolution as temporal accuracy.
